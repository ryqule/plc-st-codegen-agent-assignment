# Automated ST functional tests

`P02_test.st` turns the three P02 dataset scenarios into scan-by-scan assertions: zero on the first call, exact rising/falling masks after `16#0F -> 16#13`, and no edges when the input repeats. It adds two boundary cases for all 32 bits rising and then all 32 bits falling. `__POU_NAME__` is filled from the generated ST declaration by `tools/run_st_tests.py`.

The executed test engine was STruC++ 0.7.0. It compiles the ST POU and the test file into a native test runner, then executes the assertions. All four P02 outputs (Pi/self × GPT/DeepSeek) passed 5/5 tests. DeepSeek Pi uses `SHR` followed by a one-bit mask; because STruC++ 0.7.0 rejects that nested-parenthesis form, the runner applies and records the equivalent `AND SHL(1, bitIndex)` form for this exact idiom. The original ST file and hash remain unchanged, and the executed-source hash is recorded separately.

This is an independent ST execution engine; it supplements the recorded CODESYS compiler results and does not claim CODESYS Control Win runtime equivalence. The tests cover P02 only, not all 112 dataset scenarios.

Install the Windows x64 release (0.7.0 for the archived result) from the [official STruC++ releases](https://github.com/Autonomy-Logic/STruCpp/releases). Pass its executable with `--strucpp` or set `STRUCPP_EXE`. Run from the repository root; this example writes into the ignored local-run directory:

```powershell
py tools/run_st_tests.py `
  --source st/runs/pi/deepseek/P02.st `
  --test-template tests/structured_text/P02_test.st `
  --strucpp C:\path\to\strucpp.exe `
  --result experiments/local_runs/P02_pi_deepseek.json
```

Each JSON result includes the tool path, POU name, source and test-template SHA256, test count, pass/fail count, and runner output. The committed JSON files in `experiments/functional_tests/` are the archived 20/20 evidence; do not overwrite them when repeating the test. The current reported runs cover P02 generated by both Agent frameworks and both models; they do not execute all 112 dataset scenarios.

## CODESYS Control Win runtime smoke test

`P02_runtime_vectors.json` is the machine-readable five-case scan-level oracle. `P02_runtime_driver.st` runs each case in an isolated function-block instance on a 50 ms cyclic task, records pass/fail per case, and exposes the actual output values for inspection. No physical I/O is mapped.

Build the test project with the installed CODESYS profile and write artifacts under the ignored `experiments/local_runs/` directory:

```powershell
py tools/run_p02_codesys_runtime.py `
  --output-dir experiments/local_runs/codesys_runtime/P02_smoke
```

To download and run it on the local Control Win runtime, start **CODESYS Control Win V3 x64** first, enter the test account credentials into the current PowerShell process as shown in `docs/REPRODUCING.md`, then add `--run`:

```powershell
py tools/run_p02_codesys_runtime.py `
  --run `
  --output-dir experiments/local_runs/codesys_runtime/P02_runtime
```

The result is `RUNTIME_PASS` only when the running POU completes all five cases with no failures. `COMPILE_PASS` means only that the CODESYS project built offline; it is not a runtime pass. The JSON records the ST source hash and per-case actual values. The username and password are read from `CODESYS_TEST_USER` and `CODESYS_TEST_PASSWORD` in the current process environment, used only for this login, and not written to artifacts.

## Bounded formal verification bonus

`tools/run_p02_cbmc.py` sends the STruC++ generated C++ function body for P02 to CBMC 5.95.1 in WSL. CBMC checks two arbitrary consecutive 32-bit state transitions against the masks, changed/edge flags, counts, and previous-value update. It also checks loop unwinding, bounds, and pointers. The initial zero state is checked by the automated test suite.

All four P02 outputs passed: 918 CBMC properties across the four outputs, with zero failures (185–261 per output). The runner retains the source/transpilation hashes, the exact checked C++ body, its minimal type header, the harness, the CBMC log, and a JSON summary under `experiments/formal_verification/`.

The check applies to the STruC++ translation of P02, not CODESYS runtime behavior. The adapter retains STruC++'s generated class fields and function bodies but substitutes IEC primitive type aliases and the `SHL` helper declaration so CBMC can parse the source without STruC++'s C++ standard-library headers. Formal verification covers P02 only; the other 29 tasks and PLCVerif are not verified.

Reproduce after installing STruC++ 0.7.0 and CBMC in WSL (Ubuntu):

```powershell
wsl -e bash -lc 'sudo apt-get update && sudo apt-get install -y cbmc'
```

Then run:

```powershell
py tools/run_p02_cbmc.py `
  --source st/runs/pi/gpt/P02.st `
  --strucpp C:\path\to\strucpp.exe `
  --output-dir experiments/local_runs/formal_verification/P02_pi_gpt
```

CBMC is the [CProver bounded model checker](https://github.com/diffblue/cbmc); STruC++ is documented in the [project test guide](https://github.com/Autonomy-Logic/STruCpp/blob/development/docs/TESTING.md).
